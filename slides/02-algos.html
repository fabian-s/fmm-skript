Gegeben Problem \(f\) mit Input \(\bx\), berechne Lösung \(f(\bx)\).

Numerische Probleme: Schwierigkeiten

  • Computer sind so gut wie nie exakt.
  • Sie können
    • … nur endliche und endlich viele Zahlen darstellen.
      • \(\pi = 3.141592653589793238462643383279\dots\) 😞
    • … nur endlich viele Berechnungen durchführen.
      • \(\displaystyle e^x = \sum_{n = 0}^\infty \frac{x^n}{n!}\) 😞
  • Deshalb ist es wichtig, wie wir Dinge berechnen!

Numerische Probleme: Schwierigkeiten

  • Computer können nur endlich viele Zahlen darstellen.
  • Das führt zu Rundungsfehlern, die sich akkumulieren können.
  • Die Reihenfolge unserer Rechenoperationen spielt eine Rolle.
  • Fehler einzelner Operationen sind oft vernachlässigbar, aber sie akkumulieren.
  • Empfehlung: Besonders große/kleine Zahlen vermeiden.

Beispiel: Katastrophale Auslöschung

Problem: Berechne die Varianz von \(\bx\) mit der Formel \[\text{Var}(\bx) = \frac{1}{n}\sum_{i=1}^n x_i^2 - \left(\frac{1}{n}\sum_{i=1}^n x_i\right)^2\]

Daten: \(\bx = (4 + 10^9,\, 7 + 10^9,\, 13 + 10^9,\, 16 + 10^9)\)

Berechnung:

x <- c(4, 7, 13, 16) + 1e9
mean((x - mean(x))^2) # Varianz (mit 1/n)
[1] 22.5
mean(x^2) - mean(x)^2 # !! auch Varianz (mit 1/n) ?!
[1] 0
  • Ursache: Subtraktion zweier fast gleich großer Zahlen (\(\approx 10^{18}\)).
mean(x^2)
[1] 1e+18
mean(x)^2
[1] 1e+18

Beispiel: Assoziativität verletzt

Problem: Gleitkomma-Addition ist nicht assoziativ!

Konkretes Beispiel: Seien \(x = 10^{30}\), \(y = -10^{30}\), \(z = 1\).

\[\begin{align*} (x + y) + z &= (\cred{10^{30}} + \cred{(-10^{30})}) + \cgreen{1} = 0 + \cgreen{1} = \cgreen{1} \\ x + (y + z) &= 10^{30} + ((-10^{30}) + \cgreen{1}) \stackrel{!!}{\approx} \cred{10^{30}} + \cred{(-10^{30})} = 0 \end{align*}\]

  • Die zweite Berechnung ergibt \(0\), weil \(1\) zu klein ist gegenüber \(10^{30}\).

\(\implies\) Reihenfolge der Summe beeinflusst Ergebnis!!

Algorithmen

Def.: Algorithmus

Ein Algorithmus ist ein Verfahren \(\wt f = \wt f_s \circ \cdots \circ \wt f_1\), das für Inputs \(\bx\) eine mögliche Lösung \(\wt f(\bx)\) des Problems \(f(\bx)\) berechnet.

Arten von Algorithmen

  • exakt: es gilt \(f(\bx) = \wt f(\bx)\) (bis auf Rundungsfehler)
    vs. approximativ: es gilt lediglich \(f(\bx) \approx \wt f(\bx)\).
  • iterativ: gleiche Vorschrift wird mehrfach ausgeführt
    vs direkt: Vorschrift wird nur einmal ausgeführt.
  • probabilistisch/randomisiert: beruht auf Zufall
    vs deterministisch: keine Zufallselemente.

Beispiel: Fibonacci-Zahlen

  • Problem: Berechne die ersten \(N\) Fibonacci-Zahlen \[\begin{align*} x_1 = 0, \quad x_2 = 1, \quad x_{n +1} = x_{n} + x_{n - 1} \; (n \ge 2). \end{align*}\]
  • Algorithmus: \[\begin{align*} \wt f &: \N \to \N^n \\ \wt f(n) &= (\wt f_{n} \circ \cdots \circ \wt f_3 \circ \wt f_2 \circ \wt f_1)(n) \\ \wt f_1(n) &= 0, \quad \wt f_2(x) = (x,1), \\ \wt f_{i+1}(x_1,\dots,x_i) &= (x_1,\dots,x_i,x_i+x_{i-1}) \quad (i \ge 2). \end{align*}\]

Fibonacci: Implementierung

  • Implementierung des Algorithmus:
fibonacci <- function(n) {
  x <- numeric(n)  # Vektor (0, ..., 0) der Länge n
  if (n > 1) {
    x[2] = 1
  }
  if (n > 2) {
    for (i in 2:(n-1)) {
      x[i+1] <- x[i] + x[i - 1]
    }
  }
  x
}
  • Beispiel (\(n = 6\); schrittweise Rechnung s. Anhang):
fibonacci(6)
[1] 0 1 1 2 3 5

Algorithmenarten in ML / Statistik

  • Exakt/direkt:
    • LGS-Lösung via Gauß-Elimination (später…)
    • Matrixmultiplikation
  • Approximativ:
    • Monte-Carlo-Integration (schätzt Integrale durch Stichproben)
    • Neuronale Netze (optimieren bis zu einem Toleranzlevel)
  • Iterativ:
    • Gradientenabstieg in Machine Learning
    • Newton-Verfahren zum Nullstellenfinden
  • Probabilistisch:
    • Approximative Singulärwertzerlegung, Matrix Sketching
    • MCMC-Methoden in Bayesianischer Statistik

Oft kombiniert: ML-Algorithmen sind oft iterativ + approximativ + probabilistisch!

Aufwand und Komplexität

Aufwand und Komplexität

  • Der Computer führt einen Algorithmus durch elementare Operationen aus: Rechenoperationen \(f_i\in\lbrace +, -, \cdot, /\rbrace\), aber auch Vergleiche, Zuweisungen und Speicherzugriffe — jede mit (etwa) konstantem Aufwand.
  • Der Zeitaufwand des Algorithmus ist die Anzahl dieser Operationen.
    • höherer Aufwand \(\approx\) längere Laufzeit
  • Der Speicheraufwand ist (in etwa) die Anzahl der (zwischen-)gespeicherten Zahlen.
    • höherer Aufwand \(\to\) mehr Speicherplatz

Beispiel: Matrix-Vektor-Multiplikation

Problem: Berechne \(\by = \bA\bx\) für \(\bA \in \R^{3 \times 2}\), \(\bx \in \R^2\).

Konkret: \(\bA = \begin{pmatrix} \cblue{1} & \cblue{2} \\ \cgreen{3} & \cgreen{4} \\ \corange{5} & \corange{6} \end{pmatrix}\), \(\bx = \begin{pmatrix} \cpurp{7} \\ \cpurp{8} \end{pmatrix}\)

Berechnung: \[\begin{align*} \cblue{y_1} &= \cblue{1} \cdot \cpurp{7} + \cblue{2} \cdot \cpurp{8} = \cblue{7 + 16 = 23} \quad \text{(2 Mult., 1 Add.)} \\ \cgreen{y_2} &= \cgreen{3} \cdot \cpurp{7} + \cgreen{4} \cdot \cpurp{8} = \cgreen{21 + 32 = 53} \quad \text{(2 Mult., 1 Add.)} \\ \corange{y_3} &= \corange{5} \cdot \cpurp{7} + \corange{6} \cdot \cpurp{8} = \corange{35 + 48 = 83} \quad \text{(2 Mult., 1 Add.)} \end{align*}\]

  • Zeitaufwand: \(3 \times 2 = 6\) Multiplikationen + \(3 \times 1 = 3\) Additionen \(= 9\) Operationen
  • Allgemein: Für \(\bA \in \R^{n \times d}\): \(nd\) Multiplikationen + \(n(d-1)\) Additionen \(\approx 2nd\) Operationen
  • Speicheraufwand: \(nd\) (für \(\bA\)) + \(d\) (für \(\bx\)) + \(n\) (für \(\by\)) \(= nd + n + d\) Zahlen

Quiz: Zeit- und Speicheraufwand

Sei \(\bA \in \R^{n \times d}\), \(\bx, \by \in \R^d\), \[f(\bA, \bx, \by) = \bA(\bx - \by) = \sum_{i = 1}^d (x_i - y_i) \bA_{\cdot i}.\]

f <- rep(0, nrow(A))
for (i in 1:ncol(A)) {
  f <- f + (x[i] - y[i]) * A[, i]
}

a) Wie viele elementare Rechenoperationen werden benötigt?

  1. \(2n + d\)
  2. \(2dn + d\)
  3. \(dn^2\)
  4. \(2(n + d)\)

b) Für wie viele Gleitkommazahlen brauchen wir Speicherplatz?

  1. \(3n + d\)
  2. \(4nd\)
  3. \(2(n + d)\)
  4. \(n + nd + 2d\)

Quiz: Lösung

a) Zeitaufwand: \(2nd + d\) Operationen

Aufschlüsselung pro Iteration (\(i = 1, \ldots, d\)):

  1. Subtraktion: \((x_i - y_i) \to\) 1 Operation
  2. Skalierung: \((x_i - y_i) \cdot \bA_{\cdot i} \to n\) Multiplikationen (1 Element/Zeile f. \(\bA_{\cdot i}\))
  3. Addition: f <- f + ... \(\to n\) Additionen

Pro Iteration: \(1 + n + n = 2n + 1\) Operationen

Gesamt: \(d \times (2n + 1) = 2nd + d\) Operationen


b) Speicheraufwand: \(n + nd + 2d\) Gleitkommazahlen

  • \(n\) (für f) + \(nd\) (für \(\bA\)) + \(2d\) (für \(\bx\) und \(\by\))

Komplexität

  • Die exakte Anzahl an Operationen und gespeicherten Zahlen zu kennen, ist nicht wichtig.
  • Wir sind hauptsächlich daran interessiert wie schnell der Aufwand mit der Größe des Problems wächst (“skaliert”).
  • Das nennen wir (Laufzeit-/Speicher-)Komplexität des Algorithmus.

Komplexität

Beispiel:

  • Ein Algorithmus benötigt \(4n^3 + 16n^2 + 239\) Operationen.
  • Für großes \(n\) ist \(16n^2 + 239\) gegenüber \(4n^3\) vernachlässigbar.

\(\implies\) Der Algorithmus skaliert wie \(4n^3\),
die Komplexität ist kubischer Ordnung: “\(O(n^3)\)”.

Komplexitätsklassen

Komplexitätsklassen

Wie verschiedene Komplexitäten skalieren:

Interpretation:

  • \(O(1)\) (konstant):
    Anzahl Operationen ist unabhängig von \(n\)
  • \(O(\log_b n)\) (logarithmisch):
    eine Operation mehr falls sich \(n\) ver-\(b\)-facht.
  • \(O(n)\) (linear):
    verdoppelt sich \(n\), verdoppeln sich Operationen
  • \(O(n^2)\) (quadratisch):
    verdoppelt sich \(n\), vervierfachen sich Operationen
  • \(O(2^n)\) (exponentiell):
    verdoppelt sich \(n\), exponentieren sich Operationen

Vorsicht:

\(O()\)-Notation ignoriert konstante Faktoren und Terme – z.B.

  • \(1000n + 10 000\) Operationen sind immer noch \(O(n)\)
  • aber (viel) langsamer als \(n^2\) Operationen (\(O(n^2)\)) für \(n < 1010\)!

Landausymbole

Def.: Landausymbole

Seien \(a_n, b_n\) Folgen mit \(b_n \neq 0\).

  • \(a_n = o(b_n)\) (,,\(a_n\) ist klein-o von \(b_n\)”), wenn \[\begin{align*} \lim_{n \to \infty} \frac{a_n}{b_n} = 0. \end{align*}\]
  • \(a_n = O(b_n)\) (“\(a_n\) ist groß-O von \(b_n\)”), wenn \[\begin{align*} \operatorname{lim sup}_{n \to \infty} \left\vert \frac{a_n}{b_n} \right\vert < \infty. \end{align*}\]

Interpretation:

  • \(a_n = o(b_n)\): \(a_n\) wächst langsamer als \(b_n\), \(a_n\) wird gegenüber \(b_n\) vernachlässigbar klein.
  • \(a_n = O(b_n)\): \(a_n\) wächst höchstens so schnell wie \(b_n\), \(b_n\) ist gegenüber \(a_n\) nicht vernachlässigbar.
  • Zusatz:
    \[a_n = \Theta(b_n)\] falls \(a_n = O(b_n)\) und \(b_n = O(a_n)\), d.h. \(a_n\) wächst genauso schnell wie \(b_n\).

Landausymbole: Rechenbeispiel

Beispiel: Zeige, dass \(3n^2 + 5n = O(n^2)\)

\[\begin{align*} \lim_{n \to \infty} \frac{\cgreen{3n^2} + \cred{5n}}{n^2} &= \lim_{n \to \infty} \left(\cgreen{3} + \cred{\frac{5}{n}}\right) = \cgreen{3} < \infty \\ \implies 3n^2 + 5n &= O(n^2) \quad \checkmark \end{align*}\]

Weitere Rechenbeispiele: siehe Anhang

Landausymbole

  • Meist suchen wir eine möglichst einfache Folge \(b_n\), sodass \(a_n = O(b_n)\) aber nicht \(a_n = o(b_n)\).

Lemma: Ein paar Rechenregeln

Seien \(a_n, b_n > 0\) (z.B. Anzahl von Operationen).

  1. Sei \(f_n=O(a_n)\) und \(g_n=O(b_n)\). Dann gilt \[\begin{equation*} f_n + g_n = O(a_n + b_n) \quad\text{und}\quad f_n \cdot g_n = O(a_n \cdot b_n). \end{equation*}\]
  2. Sei \(f_n=O(a_n)\) und \(g_n=o(b_n)\). Dann gilt \[\begin{equation*} f_n \cdot g_n = o(a_n \cdot b_n) \end{equation*}\]
  3. Sei \(f_n = O(a_n + b_n)\) mit \(a_n = O(b_n)\). Dann gilt \[\begin{equation*} f_n = O(b_n). \end{equation*}\]

Rechenregeln: Anwendungsbeispiele

Beispiel Addition und Multiplikation:

Gegeben: \(f_n = 3n^2 = O(n^2)\) und \(g_n = 5n = O(n)\)

\[\begin{align*} \text{Addition:} \quad f_n + g_n &= \cgreen{3n^2} + \cred{5n} = O(\cgreen{n^2} + \cred{n}) = O(\cgreen{n^2}) \\ & \text{(wegen Regel 3: } \cred{n} = O(\cgreen{n^2}) \text{)} \\[0.5em] \text{Multiplikation:} \quad f_n \cdot g_n &= (3n^2) \cdot (5n) = 15n^3 = O(n^2 \cdot n) = O(n^3) \end{align*}\]

Beispiel Vereinfachung:

Gegeben: Algorithmus benötigt \(4n^3 + 16n^2 + 239\) Operationen.

\[\begin{align*} \cgreen{4n^3} + \cred{16n^2 + 239} &= O(\cgreen{n^3} + \cred{n^2 + 1}) \\ &= O(\cgreen{n^3}) \quad \text{(da } \cred{n^2} = O(\cgreen{n^3}) \text{ und } \cred{1} = O(\cgreen{n^3}) \text{)} \end{align*}\]

\(\implies\) Wir können komplexe Ausdrücke auf dominanten Term reduzieren!

Fibonacci: Komplexitätsanalyse 1

Iterativer Algorithmus:

fibonacci <- function(n) {
  x <- numeric(n)
  if (n > 1) {
    x[2] = 1
  }
  if (n > 2) {
    for (i in 2:(n-1)) {
      x[i+1] <- x[i] + x[i - 1]
    }
  }
  x
}

Zeitkomplexität:

  • Initialisierung: x <- numeric(n) → \(O(n)\)
  • Schleife: \(n-2\) Iterationen mit je konstant vielen Operationen (1 Addition + Indexrechnung) → \(O(n)\)
  • Gesamt: \(O(n)\) (linear)

Speicherkomplexität:

  • Vektor x mit \(n\) Elementen → \(O(n)\)

Fibonacci: Komplexitätsanalyse 2

Naive Rekursion:

fib_recursive <- function(n) {
  if (n <= 1) {
    return(n)
  }
  return(
    fib_recursive(n-1) +
    fib_recursive(n-2)
  )
}
  • Zeitkomplexität:
    jede Iteration macht 2 Aufrufe, die wiederum je 2 Aufrufe machen, usw.
    \(\implies\) insgesamt \(O(2^n)\), also exponentiell!
    katastrophal langsam
  • Speicherkomplexität:
    \(O(n)\) (Rekursionstiefe)

Live: Laufzeit in Sekunden für \(n = 30\) –

system.time(fibonacci(30))["elapsed"]
elapsed 
  0.024 
system.time(fib_recursive(30))["elapsed"]
elapsed 
   4.27

\(\implies\) Iterative Lösung ist dramatisch effizienter (\(\times 180\)) – und liefert dabei sogar alle ersten \(n\) Zahlen, während die Rekursion nur \(F_n\) berechnet!

Zusammenfassung

Fibonacci: Schrittweise Berechnung

Berechne die ersten 6 Fibonacci-Zahlen (\(n = 6\)):

\[\begin{align*} \wt f_1(6) &= 0 \\ \wt f_2(\wt f_1(6)) = \wt f_2(0) &= (0, 1) \\ \wt f_3(\cblue{0}, \cblue{1}) &= (0, 1, \cgreen{1}) \\ \wt f_4(0, \cblue{1}, \cblue{1}) &= (0, 1, 1, \cgreen{2}) \\ \wt f_5(0, 1, \cblue{1}, \cblue{2}) &= (0, 1, 1, 2, \cgreen{3}) \\ \wt f_6(0, 1, 1, \cblue{2}, \cblue{3}) &= (0, 1, 1, 2, 3, \cgreen{5}) \end{align*}\]

Ergebnis: \(\wt f(6) = (0, 1, 1, 2, 3, 5)\)

Landausymbole: Weitere Rechenbeispiele

Beispiel 2: Zeige, dass \(5n = o(n^2)\)

\[\begin{align*} \lim_{n \to \infty} \cgreen{\frac{5n}{n^2}} &= \lim_{n \to \infty} \cgreen{\frac{5}{n}} = \cgreen{0} \implies 5n = o(n^2) \quad \checkmark \end{align*}\]

Beispiel 3: Ist \(n^2 = O(n)\)? Nein!

\[\begin{align*} \lim_{n \to \infty} \cgreen{\frac{n^2}{n}} &= \lim_{n \to \infty} \cgreen{n} = \cgreen{\infty} \quad \text{(divergiert!)} \\ \implies n^2 &\neq O(n) \end{align*}\]
